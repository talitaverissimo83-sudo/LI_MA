Desenvolvimento Back-End em Aplicações Web

Entendendo o que acontece por trás de um site: servidores, APIs, bancos de dados e tecnologias Back-End.

Front-End x Back-End Funcionamento APIs Tecnologias Aplicação real Referências

Pergunta principal

“Quando o usuário clica em um botão no site, o que está acontecendo no Back-End?”

Quando o usuário clica em um botão, o navegador pode enviar uma requisição para o servidor. O Back-End recebe essa requisição, verifica os dados, executa as regras necessárias e pode consultar ou alterar um banco de dados. Depois disso, ele envia uma resposta para o Front-End.

1. Front-End e Back-End

O que é Front-End?

Front-End é a parte de uma aplicação que o usuário consegue visualizar e utilizar. Ele envolve a aparência da página, os botões, menus, textos, imagens e formulários.

As principais tecnologias utilizadas no Front-End são HTML, CSS e JavaScript.

O que é Back-End?

Back-End é a parte da aplicação responsável pelo funcionamento interno do sistema. Ele recebe informações, processa dados, aplica regras de negócio, trabalha com bancos de dados e pode fornecer APIs.

Diferenças entre Front-End e Back-End

Front-End Back-End
É a parte visual do site. É a parte responsável pelo processamento.
É executado principalmente no navegador. É executado principalmente no servidor.
Utiliza HTML, CSS e JavaScript. Pode utilizar Python, Java, PHP, JavaScript, C# etc.
Interage diretamente com o usuário. Trabalha com dados, regras e bancos de dados.

Como eles se comunicam?

Front-End e Back-End normalmente se comunicam através da internet utilizando protocolos como HTTP e HTTPS. O Front-End envia uma requisição para o servidor e recebe uma resposta.

Onde o Back-End é executado?

O Back-End é executado em um servidor. Esse servidor pode ser um computador físico, uma máquina virtual ou um serviço de computação em nuvem.

2. Funcionamento do Back-End

Cliente e servidor

O cliente normalmente é o navegador que o usuário está utilizando. O servidor é responsável por receber as requisições e fornecer os dados ou serviços solicitados.

Requisição e resposta

A requisição é uma mensagem enviada pelo cliente para o servidor. Depois de processar essa solicitação, o servidor envia uma resposta para o cliente.

HTTP e HTTPS

HTTP é um protocolo utilizado para comunicação entre navegadores e servidores na Web. HTTPS utiliza uma conexão protegida por TLS, aumentando a segurança durante a transmissão dos dados.

Servidor Web

O servidor Web recebe requisições HTTP e envia os recursos solicitados. Em aplicações dinâmicas, ele também pode encaminhar as requisições para o código do Back-End.

Regras de negócio

Regras de negócio são as regras que determinam como uma aplicação deve funcionar.

Por exemplo, em uma loja virtual, uma compra só pode ser realizada se o produto estiver disponível no estoque.

Validação de dados

O Back-End também verifica se os dados recebidos são válidos. Por exemplo, pode verificar se um e-mail possui um formato correto ou se determinado usuário possui permissão para realizar uma ação.

O que acontece quando o usuário realiza uma ação?

  1. O usuário clica em um botão.
  2. O Front-End prepara os dados.
  3. O navegador envia uma requisição ao servidor.
  4. O Back-End recebe a requisição.
  5. Os dados são validados.
  6. As regras de negócio são verificadas.
  7. O Back-End pode consultar um banco de dados.
  8. O servidor cria uma resposta.
  9. A resposta volta para o Front-End.
  10. O usuário vê o resultado na tela.

3. APIs

O que é uma API?

API significa Application Programming Interface. Ela permite que diferentes partes de um sistema possam se comunicar e trocar informações.

Para que serve uma API?

Uma API pode ser utilizada para permitir que o Front-End solicite informações ao Back-End. Por exemplo, uma página pode pedir ao servidor a lista de produtos disponíveis em uma loja.

O que é API REST?

REST é um estilo de arquitetura utilizado para criar serviços Web. APIs REST geralmente utilizam métodos HTTP para realizar operações sobre recursos e frequentemente utilizam JSON para enviar dados.

O que são endpoints?

Endpoint é um endereço específico de uma API. Ele representa um recurso ou uma operação.

Exemplo:

/api/produtos

Métodos HTTP

Método Função Exemplo
GET Consultar dados. GET /api/produtos
POST Criar um novo recurso. POST /api/produtos
PUT Atualizar ou substituir um recurso. PUT /api/produtos/10
PATCH Alterar apenas uma parte do recurso. PATCH /api/produtos/10
DELETE Excluir um recurso. DELETE /api/produtos/10

Exemplo de código

fetch("/api/produtos")
    .then(resposta => resposta.json())
    .then(produtos => {
        console.log(produtos);
    });

Nesse exemplo, o Front-End faz uma requisição para buscar os produtos através da API.

5. Análise de uma aplicação real

Exemplo: loja virtual

Imagine uma loja virtual onde existe um botão chamado “Comprar”.

  1. O usuário clica no botão “Comprar”.
  2. O Front-End envia uma requisição POST para o endpoint /api/pedidos.
  3. O Back-End recebe as informações do pedido.
  4. O servidor verifica se os dados estão corretos.
  5. O Back-End consulta o banco de dados para verificar o produto e o estoque.
  6. Se houver estoque, o sistema registra o pedido.
  7. O estoque pode ser atualizado no banco de dados.
  8. O Back-End envia uma resposta para o Front-End.
  9. O Front-End mostra uma mensagem informando que o pedido foi criado.

Portanto, um simples clique pode iniciar várias operações no Back-End antes que o usuário veja o resultado na tela.

Exemplo de resposta da API

{
    "pedido": 125,
    "status": "criado",
    "mensagem": "Pedido criado com sucesso"
}

Conclusão

O Back-End é uma parte fundamental das aplicações Web. Ele é responsável por processar informações, aplicar regras de negócio, validar dados, trabalhar com bancos de dados e responder às solicitações do Front-End.

Assim, quando um usuário clica em um botão, muitas vezes existe uma sequência de operações acontecendo no servidor antes que o resultado apareça na tela.
